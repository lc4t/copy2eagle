# Bug 004 — v1.5.3 Correctness Hotfix

## Intent

修复 v1.5.2 发布准备度审计发现的状态机与配置一致性问题，使核心行为达到 Eagle Plugin Center 真机验收前置条件。

## Constraints

- 不改变插件单一用途和默认用户流程。
- 不依赖新增第三方包。
- 保持 `serviceMode: true`、全本地处理和现有配置兼容。
- 本任务不决定商店名称、正式 Plugin ID 或 License。
- Eagle 宿主的交互式路径仍需真实 Eagle 人工验证。

## Decision

1. 双实例机制改为单 owner lease：
   - owner 每轮开始时续租；
   - 非 owner 只观察，不覆盖 owner；
   - lease 时长覆盖最大 5 秒轮询与 5 秒错误重试；
   - 停用和退出时仅 owner 释放自己的 lease。
2. 将剪贴板同 hash 判定抽成可测试的纯函数：
   - `skip` 永久跳过；
   - `allow` 只在 30 秒内防抖，窗口结束后允许再次导入。
3. 所有活跃路由文件夹通过共享队列按顺序回填，覆盖启动、启用、面板重新显示、手动刷新和运行中修改路由；generation guard 保证快速连续操作时仅最新配置恢复 polling。
4. 命名模板的 `{count}` / `{lifetime}` 使用“含本次”的下一值，并在跨日首张导入前先刷新今日计数。
5. 使用 Node 内置能力增加无依赖回归检查，打包时继续生成可读 bundle。

## Impact

- 影响模块：`instance` / `poll` / `plugin` / `folders` / `import` / `ui` / build scripts。
- 配置 schema 不变，无迁移。
- 回滚方式：回退 v1.5.3 commit，恢复 v1.5.2。
- 启动和启用时会依次确认所有已配置路由文件夹的去重记录，首次启动时间可能略增，但避免错误重复导入。

## Learnings

- 双实例兼容需要把新 owner lease 与旧 heartbeat 分成两个 key；否则旧协议的抢写会继续污染新协议选举。
- owner 续租不能依赖业务 polling，因为 adaptive 和错误重试都会拉长业务轮询间隔。
- 运行中修改路由必须先暂停 polling、回填新目标，再恢复，否则去重集合会短暂缺失。
- 计数 token 的语义应明确是“当前值”还是“含本次值”，并用跨日首张导入做回归。
- serviceMode 插件首次启动会等待目标文件夹哈希回填；大型文件夹应以 `backfill done` 日志为监听就绪信号。
