# Bug 003 — v1.5.2 Release Readiness Audit

## Intent

确认 v1.5.2 已知问题是否全部修复，以及项目是否满足 Eagle Plugin Center 上架门禁。

## Constraints

- 宿主行为只能在真实 Eagle 中完成最终验证。
- Plugin Center 要求功能完整可测试、macOS/Windows 兼容、至少 256x256 PNG 图标，并建议至少 3 张真实截图。
- 本次只做审计和文档记录，不修改插件行为或产品名称。

## Decision

当前结论为“不具备直接上架条件”。建议先起 v1.5.3 correctness hotfix，再处理名称、正式 Plugin ID、审核材料和商店资产。

> 2026-06-13 更新：下列 6 个行为问题已由 Bug 004 / M17 在 v1.5.3 修复并通过自动检查；商店资产、正式 ID、License 决策和 Eagle 真机证据仍未完成。

发现的行为问题：

1. 双实例冲突分支仍写自己的 heartbeat，两个实例会交替覆盖锁并同时停止导入。
2. heartbeat 只在少数成功路径续期；同图、混排跳过、文件 URL 等提前返回路径会让锁过期。
3. `duplicateStrategy=allow` 在通用同 hash 提前返回处被拦截，30 秒后仍不能再次导入。
4. 插件随 Eagle 启动恢复监听时只回填主文件夹，额外路由文件夹没有回填。
5. 运行中修改截图/剪贴板/多文件路由只保存配置，没有为新目标文件夹回填去重集合。
6. 命名模板 `{count}` / `{lifetime}` 在计数递增前渲染，值比“含本次”的规格少 1。

发现的发布问题：

1. `manifest.json.id` 仍是占位值 `CLIPBOARD_WATCHER_001`。
2. `logo.png` 仅 128x128、无透明通道，且是占位图；官方要求至少 256x256 PNG。
3. 没有封面和真实产品截图；项目证据目录也没有 Eagle 端到端验收截图。
4. 商店材料、README 和 release checklist 仍停在 v1.0.0，实际最新版本是 v1.5.2。
5. README 仍称仓库 private、Issues 待开放，但 GitHub 当前为 public 且 Issues 已开放。
6. 最终 `.eagleplugin` 未包含 reviewer README；插件实际会调用系统进程。

## Evidence

- GitHub：开放 issue 数量为 0；#1、#2 均已关闭；最新 release 为 v1.5.2。
- `npm run pack`：通过，产物含 manifest/index/logo/bundle 共 4 个文件；`node --check` 全部通过。
- 双实例模拟：B 看到 A 后写 B，A 再看到 B 后写 A，冲突持续循环。
- 代码位置：
  - `js/lib/poll.js`：冲突分支写 heartbeat；同 hash 在 allow 策略前提前返回。
  - `js/plugin.js`：启动恢复只回填主 folder；路由 UI 保存配置后不回填。
  - `js/lib/import.js`：名称在 `incrementToday()` 前生成。
- 资产检查：`logo.png` 为 128x128 RGB PNG，无 alpha。
- 官方资料核验日期：2026-06-13，详情见 `.agent-doc/knowledge.md` K16。

## Impact

- 双实例场景可能从“重复导入”退化成“两个实例都不导入”。
- allow 重复策略和多文件夹去重不符合已声明行为。
- 若直接提交，功能审核、资产审核和 reviewer 可测试性均有被拒风险。
- 改 manifest ID 会让既有本地安装成为不同插件，需明确卸载旧版和重新配置的迁移说明。

## Learnings

- 心跳互斥不能由冲突方覆盖 owner；需要稳定 owner/lease 规则，并让 owner 独立续期。
- 多路由配置的索引生命周期必须覆盖启动、启用和运行中改路由三个入口。
- “GitHub issue 已关闭”不等于行为已验证，发布结论必须同时看代码路径与真机证据。
- 商店材料必须随最新 release 更新，不能复用早期版本的占位资产和旧状态文案。
